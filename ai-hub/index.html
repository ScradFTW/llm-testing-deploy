Self-hosted ML infrastructure

Five small, real, running systems on a single $5/mo 1-vCPU / 2GB VPS — built to demonstrate the production side of ML/LLM/CV work: serving, evaluation, guardrails, and observability, across both text and vision. Written for anyone reviewing this as part of an interview.

Every backend service: runs as its own unprivileged systemd user, binds to 127.0.0.1 only (never reachable except through nginx), has a hard MemoryMax, and is sandboxed (ProtectSystem=strict, NoNewPrivileges). Same pattern repeated across every service rather than one-off setups — the kind of consistency that matters once there's more than one service to operate.

Honest gaps

This runs on one $5/mo VPS, not a cloud platform, on purpose — the point was to demonstrate engineering judgment under a real, tight constraint, not to simulate a fleet. That means some things a production system at scale would have are deliberately not here:

  • No cloud platform (AWS/GCP) or IaC — this is a single Linode VPS configured directly; no Terraform, no infra-as-code. At scale this would be Terraform-managed, likely across environments.
  • No containers/orchestration — each service is a systemd unit on bare metal, not Docker/Kubernetes. Right-sized for five services on one box; wrong choice past that.
  • No CI/CD — deploys are manual (documented in the repo). A real pipeline would run each model's eval suite as a gate before any deploy.
  • No GPU serving — the vision model was trained on GPU, but both models serve on CPU only, by necessity of the VPS hardware. Latency-sensitive, larger-scale serving would need GPU fleets, batching, and a real inference server (vLLM/TensorRT-LLM).
  • Not a true multi-modal model — the text and vision classifiers are two separate models behind separate tools, not one model reasoning jointly over both modalities (a real VLM). The agent also doesn't call the vision tool yet — extending it to accept an image is the natural next step, not yet done.
  • No agent framework (LangGraph/Temporal/etc.) — one tool and one decision point doesn't need one; multi-tool, multi-step agents would.

None of this is hidden — it's the same list in the project's README, and happy to go deeper on any of it.

Built with Claude Code

Every part of this — the systemd units, nginx config, model training and evaluation scripts, the orchestrator, this page — was built in collaboration with Claude Code. That included it making real mistakes worth mentioning rather than hiding: a font-stack bug that made an entire page's text invisible, a port collision with an unrelated project on the same box, and a naive first version of the tool-calling guardrail that had to be corrected after testing showed the model hallucinating tool calls. Reviewing, testing, and catching that — not just accepting generated output — was part of the exercise.

Questions about any piece of this are welcome — that's the point of writing it down.
